# instalar-local -- OpenCode mirror

Generated by `scripts/portabilidad_agentes.py`. Edit the canonical contract and re-run `generar`; edits made straight to this file are overwritten on the next run.

This is a thin mirror. It gives OpenCode its own discovery path for a command that is fully defined somewhere else, and it holds no domain rule of its own.

## Read this first

- `.claude/commands/instalar-local.md` is the complete contract: persona, invariants, run sequence and output shape. Read it before doing anything.

## Invocation

```text
/instalar-local
```

Everything typed after the command name arrives as `$ARGUMENTS`.

## Runtime notes

- **Repository root.** Resolve it with `git rev-parse --show-toplevel 2>/dev/null || pwd` and run every command from there. Do not trust the process working directory: in OpenCode Desktop it can resolve to the app data directory instead of the project.
- **Environment.** Every CLI verb runs as `PYTHONPATH=src .venv/bin/python -m ...`. Do not reach for bare `python`/`python3` first, and do not report the environment as missing just because they cannot import `chec_local_interpreter`: the virtualenv-prefixed form is this repository's supported local command.

## Boundaries

- No external LLM API call. The agent reading this file is the one that reasons; the Python side only builds context and validates shape.
- No automatic publishing and no `site/assets/site/results/` mutation. Publishing is a separate, deliberate action.
- No model training and no Optuna search.
- No business logic here. Preparation, simulation, inference, alignment, validation and rendering stay in the canonical pipeline.
- Generated technical artifacts stay in English unless the user asks otherwise.
